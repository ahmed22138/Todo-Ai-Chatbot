## Prompt

You are a senior AI architect and spec-driven development expert.

Create a complete SP.CONSTITUTION for Phase III: Todo AI Chatbot using MCP architecture.

System Rules:
- No manual coding by humans
- All implementation must be generated via Claude Code
- Backend must be stateless
- Conversation and task state must persist in PostgreSQL
- AI must interact ONLY via MCP tools

Objectives:
- Natural language todo management
- MCP-based tool invocation
- Stateless chat endpoint
- Persistent conversation history
- OpenAI Agents SDK for reasoning

Architecture Constraints:
- FastAPI backend
- SQLModel ORM
- Neon Serverless PostgreSQL
- OpenAI Agents SDK
- Official MCP SDK
- ChatKit frontend
- Better Auth for authentication

Agent Rules:
- The agent must NEVER manipulate the database directly
- The agent must ONLY use MCP tools
- Each user action must result in a friendly confirmation
- Errors must be handled gracefully
- Tool calls must be logged and returned in API response

MCP Tool Rules:
- add_task, list_tasks, complete_task, update_task, delete_task
- All tools must be stateless
- Tools must store state only in database

Conversation Rules:
- Server must fetch full conversation history per request
- Server must store every user and assistant message
- Server must NOT keep memory between requests

Deliverables:
- Frontend, Backend, MCP server, Specs
- Fully working AI chatbot
- Clean, testable, scalable architecture

Output:
- A clear, structured SP.CONSTITUTION document
- No code
- No explanations outside the spec

## Response snapshot

Created comprehensive constitution v1.0.0 for Todo AI Chatbot with eight core principles:

1. **MCP-Only Tool Interface** - Agent uses ONLY MCP tools, no direct database/filesystem access
2. **Stateless Backend Architecture** - FastAPI holds no conversation/session state between requests
3. **Persistent Conversation Memory** - All messages stored in PostgreSQL before processing/returning
4. **Agent-Driven Implementation** - All code generated by Claude Code via /sp.* commands
5. **Database Isolation** - Agent never sees database schema/queries, only tool interfaces
6. **Friendly Error Handling** - User-facing messages natural language, technical errors logged internally
7. **API-First Design** - REST endpoints as single source of truth, OpenAPI documented
8. **Test-First Development** - When tests required, write→fail→implement→pass cycle

Architecture Constraints define:
- Technology stack (FastAPI, SQLModel, Neon PostgreSQL, OpenAI Agents SDK, MCP SDK, ChatKit, Better Auth)
- MCP tool specification (add_task, list_tasks, complete_task, update_task, delete_task)
- API design standards (POST /api/chat, response format)
- Database schema (users, conversations, messages, tasks)

Development Workflow establishes:
